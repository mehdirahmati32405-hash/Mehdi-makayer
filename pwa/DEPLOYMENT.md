# راهنمای انتشار مستقل PWA گزارش شهروندی ملایر

## وضعیت فعلی
این اپ در شاخه `pwa-phase1` و پوشه `pwa/` قرار دارد. ربات تلگرام در شاخه `main` اجرا می‌شود. برای جلوگیری از اختلال، فعلاً شاخه اپ را با main ادغام نکنید و تنظیمات FadeHost ربات را تغییر ندهید.

## روش پیشنهادی انتشار
1. یک پروژه وب مستقل با نامی مانند `malayer-citizen-pwa` در میزبان استاتیک ایجاد کنید.
2. مخزن `mehdirahmati32405-hash/Mehdi-makayer` و شاخه `pwa-phase1` را به آن وصل کنید.
3. Root Directory را دقیقاً روی `pwa` بگذارید.
4. چون برنامه فایل استاتیک HTML/CSS/JS است، Build Command را خالی بگذارید و خروجی را از همان پوشه سرو کنید.
5. HTTPS را فعال کنید؛ Service Worker فقط در secure context (HTTPS یا localhost) قابل استفاده است.
6. ابتدا با آدرس Preview آزمایش کنید. تا پایان آزمایش، دامنه عمومی یا اتصال به داده‌های واقعی را فعال نکنید.

## چک‌لیست آزمایش قبل از انتشار
- صفحه اصلی در موبایل و دسکتاپ باز می‌شود.
- راست‌چین بودن و فیلدهای فرم درست نمایش داده می‌شوند.
- دکمه ثبت فقط گزارش آزمایشی در همان صفحه می‌سازد.
- اجازه موقعیت‌یابی ردشده یا پذیرفته‌شده، برنامه را از کار نمی‌اندازد.
- `manifest.webmanifest` و `icon.svg` از HTTPS در دسترس‌اند.
- Service Worker بدون خطا ثبت می‌شود.
- در حالت آفلاین، پوسته برنامه پس از بارگذاری اولیه باز می‌شود.
- هیچ توکن، رمز، داده شخصی یا متغیر محیطی ربات در بسته وب وجود ندارد.

## پیش از اتصال به سامانه واقعی
نمونه فعلی ذخیره‌سازی سروری، ورود واقعی، مجوزهای نقش‌محور، آپلود عکس یا API ندارد. برای نسخه عملیاتی باید API امن و پایگاه داده با دسترسی محدود طراحی شود. انتخاب نقش در مرورگر به‌تنهایی احراز هویت نیست. هرگز کلید service-role یا توکن ربات را در JavaScript سمت کاربر قرار ندهید.

## نکته درباره Vercel
پروژه وب باید جدا از پروژه‌های فعلی پنل مدیریت ایجاد شود. هنگام اتصال Git، شاخه `pwa-phase1` و Root Directory برابر `pwa` را انتخاب کنید تا فایل‌های اپ مستقل بمانند. قبل از تغییر تنظیمات پروژه‌های موجود، شناسه و مخزن متصل به آن‌ها را بررسی کنید.
